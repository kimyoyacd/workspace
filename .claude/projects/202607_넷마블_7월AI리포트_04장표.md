## 2026-08-04 — 리포트 범위 재정의

리포트 발송 후 넷마블(고유리 담당자)로부터 8월 실행 계획 관련 질의 메일 수신. 회신을 준비하는 과정에서 UA 룩앤필 5방향 → 제작 레버 4종 → 베리에이션 20여 종 → 실행 클리셰까지 브레인스토밍이 계속 옆으로 번지는 문제가 드러남. "1개 리포트(1 TO)가 장황해진다", "레버 4종을 리포트에서 설명하는 게 고객사 니즈와 맞는지 모르겠다"는 지적에 따라 범위를 다시 정의함.

**핵심 결정**: 리포트의 목적은 "우리는 (뭐든) AI로 시도해볼 수 있다"는 것 하나. 투입 자원(TO)이 사람이 아니라 AI로 대체된다는 증명이 본질이고, 레버·베리에이션 카탈로그는 콘텐츠가 아니라 수단이다. 리포트는 "9월 실무 니즈 → 리포트 안에서 AI로 검증 → 검증된 것을 9월 실제 제작에 바로 투입"하는 **선순환 구조**로 돌아가야 하며, 데모로 끝나는 전시성 콘텐츠는 걷어낸다.

**범위 필터** — 둘 다 "예"인 것만 리포트에 포함:
1. 9월에 고객사가 실제로 고민 중인 것에 대한 답인가?
2. 이 시도 결과가 9월 실무 제작에 바로 투입될 수 있는가 (전시용이 아닌가)?

**필터링 결과**

| 항목 | 판정 | 근거 |
|---|---|---|
| 뱀피르 파일럿 테스트 | 통과 — 리포트 핵심 | 고객사가 이메일에서 직접 요청 |
| 우선순위 3타이틀(세나리버스·칠대죄 그랜드크로스·나혼자만 레벨업) AI 후킹안 | 통과 — 리포트 핵심 | 고객사가 9월 고민거리로 명시. 조건: 일러스트·캐릭터 리소스는 AI로 생성하지 않고 초반 후킹에만 AI 사용 |
| 제작 레버 4종(배경·오브젝트·IP·규격 교체) 설명 | 탈락 → 방법론 한 줄로 축소 | 별도 섹션이 아니라 위 두 테스트를 만드는 수단일 뿐 |
| 베리에이션 카탈로그(포즈·배경·시네마그래프·LUT 등 20여 종) | 탈락 → 백로그 | 9월 니즈와 직접 연결 안 됨, "할 수 있다" 전시에 가까움 |
| 실행 클리셰 목록(가짜 유출·리액션캠 등) | 탈락 → 백로그 | 동일. 9월 특정 캠페인에서 구체 니즈가 나오면 그때 꺼낸다 |

**선순환 구조**: 9월 고민거리 파악 → 리포트 안에서 AI로 시도(증명) → 검증된 것 중 9월 제작 투입 가능한 것 추출 → 9월 실무 반영 → 결과가 다음 리포트의 다음 고민거리를 만듦 → 반복.

**다음 액션**
- 넷마블 회신 이메일의 "기타 — 확장 가능한 소재" 답변을 레버 나열식에서 벗어나 위 필터 기준으로 재작성 (다음 세션)
- `netmarble-ua-lookfeel-deck.html`의 레버 4종 부록 슬라이드를 걷어낼지는 사용자 확인 필요 — 이번 결정은 범위 정의만 다루고 덱 편집은 포함 안 함

## 2026-08-04 (계속) — 후킹 영상 제안 방식 + TO 이원화

앞선 범위 재정의에 이어, "우선순위 3타이틀 후킹안"과 "확장 가능한 소재" 두 답변을 더 구체화함.

**후킹 콘텐츠 제안 방식**: 세 타이틀(세나리버스·칠대죄 그랜드크로스·나혼자만 레벨업)에 여러 방향을 나열하지 않고, 8월 말 리포트에서 **후킹용 영상 1개**로 제안한다. 넷마블이 괜찮다고 판단하면, 9월부터 실무 기획 단계부터 이관해 진행하는 구조.

**TO 이원화 (핵심 구조 결정)**: "확장 가능한 소재가 뭐냐"는 질문에 답이 모호했던 이유는 서로 다른 두 트랙을 하나로 섞어 말했기 때문. 명확히 분리한다.
- **AI 리포트 TO** — 아직 검증 안 된 새 방향에 인사이트를 주는 용도. 파일럿 테스트, 후킹 영상 제안이 여기 속한다.
- **기존 실무 제작 TO** — 이미 만든 UA 비주얼 중 고객사가 마음에 들어 하는(위닝) 소재를 카피 베리에이션·상황 베리에이션 등으로 확장하는 것. AI 리포트를 기다릴 필요 없이, 지금 진행 중인 실무 TO로 바로 요청하면 즉시 처리된다.

**적용**: 넷마블 회신 이메일의 "우선순위 3타이틀"·"확장 가능한 소재" 두 항목을 이 구조로 재작성.

## 2026-08-04 (실장 회의, Clova Note 녹취) — 실행 세부사항 확정

실장진 미팅에서 위 "선순환 구조"·"TO 이원화"를 그대로 재확인하고, 실행 리소스와 게이트를 구체화함.

**리소스 상한**
- 8월 테스트 산출물은 하루 안팎의 작업량으로 제한. 별도 파이프라인을 새로 만들지 않고 기존 AI TO(현재 사실상 1인분 리소스)로 처리한다.
- 후킹 영상은 최대 2종까지 가능하나, 테스트 목적상 **1종으로도 충분** — 개수보다 "이 방향이 되는지" 검증이 목표.
- 완성도는 낮아도 된다. 이번 산출물은 컨셉 검증용이고, 정식 퀄리티는 실무 이관 이후에 맞춘다.

**게이트 순서**
1. 8월 안에 AI TO가 후킹 영상 테스트 1건을 만든다 (기획 지원 필요).
2. 8월 말 리포트에서 "이렇게 테스트해봤다, 괜찮은가"로 결과를 보여준다.
3. 내부 반응이 괜찮으면(1차 게이트) 9월 실무 TO로 이관 제안.
4. 실무 TO가 PO/기획을 받아 정식 스토리보드·제작 진행.
5. 이 사이클이 매달 반복 — "이번 달 테스트 → 다음 달 이관 제안"이 AI 리포트의 표준 문법.
- **세부 실행 방식(스토리보드·제작 방법 등)은 9월 이관 시점에 구체화한다.** 8월엔 테스트 자체에 집중하고 지금 단계에서 디테일까지 확정하지 않는다.

**레퍼런스**
- 과거 넷마블 나혼자만 레벨업 제안 당시 만든 "엄마가 늦잠 자는 아들을 원작 명대사로 깨우고 인게임으로 전환"하는 훅 영상 컨셉이 있음. 이번 3타이틀 후킹 테스트의 출발점으로 재활용 가능.

**이메일 선제 제안 후보 추가**
