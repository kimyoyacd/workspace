## 1. 왜 3줄 구조인가 (v10 검토 결론)

밀리의 서재 양식은 **1업무 = 1행**이다. 디자이너 1명이 한 업무를 통째로 담당하기 때문에 성립한다.

우리는 다르다. 하나의 소재를 **기획 → 이미지 → 영상 3개 직군이 릴레이로** 처리한다. 1행으로 합치면 "8/5에 0.9MD"만 남고 **어느 직군이 얼마나 붙었는지가 사라진다.** 3줄이어야 간트에서 이어달리기가 눈에 보인다.

```
소재: SOL_000120_카운트다운   고객사 전달일 8/7
  기획   최한은   8/5 ██0.5
  이미지 김민성   8/5 ██0.4
  영상   강승일        8/6 ██1.0  8/7 ██1.0
```

**→ v10의 3줄 방향은 옳다. 실행 디테일 3가지가 빠졌을 뿐이다.**

## 2. v10의 문제와 v11의 해결

| v10 문제 | v11 해결 |
|---|---|
| **고객사 전달일이 없다.** G열 목표완료일이 줄마다 따로 (샘플이 기획 8/5 / 이미지 8/5 / 영상 8/12로 제각각) → 소재를 언제 넘기는지 알 수 없음 | **G열 = 고객사 전달일**, 소재당 1개. 전달일 여유(I)·신호(H)가 블록 첫줄에 자동 표시 |
| **소재명을 3번 반복 입력.** 오타 하나면 집계가 조용히 깨짐 | 소재 = **3줄 고정 블록**. 소재명·타이틀·전달일은 첫줄만 입력, 아래 2줄은 수식 자동 상속(회색칸) |
| **행 용량 150행 = 월 50소재.** 8월 실적 82소재 | 데이터 **300행 = 월 100소재** (팀당 20소재) |
| 수량 중복입력 금지가 사람 기억에 의존 | 수량칸은 블록 첫줄 전용, 나머지 2줄은 회색 잠금 표시 |
| 전달일 넘겨 작업 중인 걸 발견 못 함 | **전달일 이후 날짜에 MD 입력 시 그 칸 빨강** |

## 3. 월 탭 컬럼

`I9` 고정(freeze)으로 A~H가 항상 보인다.

| 열 | 항목 | 입력 |
|---|---|---|
| A | No | 자동 |
| B | 게임 타이틀 | 첫줄 입력(드롭다운) → 상속 |
| C | 고객팀 | 자동 고정 |
| D | 소재명(업무명) | **첫줄 입력** → 상속 |
| E | 직군 | 프리셋 고정(기획/이미지/영상) |
| F | 담당자 | 줄마다 입력 |
| G | **고객사 전달일** | **첫줄 입력** → 상속 |
| H | **신호** | 자동 🔴지연 / 🟡임박 / 🟢여유 |
| I | **전달일 여유** | 자동 `=G - K` |
| J | 소재 총MD | 자동 `=SUM(L:L 3줄)` |
| K | 소재 최종완료일 | 자동 `=MAX(N:N 3줄)` |
| L·M·N | 직군 MD / 시작일 / 완료일 | 자동 |
| O·P·Q | 영상수 / 사이즈베리 / 다국어베리 | 첫줄 전용 |
| R·S | 상태 / 비고 | 첫줄 |
| U~AY | 31일 간트 | **실제 MD 직접 입력** (균등분산 아님) |

상단 3~6행: 일자별 **전체 / 영상 / 이미지 / 기획 TO 상태** (정원 대비 80%↑ 파랑, 초과 보라)

## 4. 색 신호

- 🔴 **빨강(날짜칸)** — 담당자 하루 1.0MD 초과, 또는 **전달일 넘겨 작업 중**
- 🟡 노랑 / 🟢 초록 — 전달일 여유 0~1일 / 2일 이상
- 회색 세로줄 — 주말·공휴일 (마스터 공휴일 목록 연동)
- 줄 배경 — 기획 주황 / 이미지 초록 / 영상 파랑

## 6. 계승한 회사 표준
- MD 환산: **1h = 0.125MD, 8h = 1.0MD** (근무 1일 = 1MD)
- 월 가동일수 20일, 담당자 1일 캐파 1.0MD
- 직군 정원: 영상 6 / 이미지 8 / 기획 3 (마스터 탭에서 수정)
- 비나(VINA) 운영 4개 시나리오는 마스터 탭에 참고 기재
