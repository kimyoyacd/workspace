## 와이어프레임 v1 (2026-08-20)

`docs/maxos/wireframe.html` — 구조 3안 병렬 비교 후 **「한 번에 하나씩」**(점진적 공개) 채택.

핵심 전환: **탭 = 정보 분류 → 탭 = 옮겨올 실제 업무 하나**
- 실장 피드백: "너무 방대", "어떻게 시작할지 감이 안 옴", "나열만 한 계획 사이트", "각 탭 정보가 이해 안 됨", "보기 좋은 수준이 아니라 실제 업무를 이식하며 문화를 바꾸는 일"
- 홈: 버튼 3개만 → 고른 뒤에만 아래가 열림. 숫자는 운영 현황 한 곳에만
- 워크플로우 지도가 사이트 중심. Figma 272-2의 `운영 디자인` 1갈래 → 하위 4종으로 확장
  (앱·웹 화면 / 상품 상세페이지 / 콘텐츠·이벤트 페이지 / 광고 배너)
- 단계 칩 = 4줄 구조: 제목 / 맡는 사람·받을 것·만들 것 / 다음 사람 ← "각 탭 정보가 이해 안 됨"에 대한 답
- 운영 현황 7탭 → 3탭 (한눈에 보기 / 진행 중인 일 / 새 일 맡을 사람)

**담당 원칙 확정 (실장 지시, 2026-08-20)**
- MAX실에 별도 운영 매니저 없음. **일을 맡은 사람이 그 일의 매니저**
- 담당자 한 명이 **1~3단계를 끝까지 이어서** 함. 단계별 역할 핸드오프 구조 폐기
- **디렉터는 방향만 컨펌** — 방향이 갈리는 단계 끝 1회. 만들기·상세 결정에는 미개입
- 컨펌 지점: 화면·페이지·배너 = 2단계 끝 / 영상·AI 이미지 = 1단계 끝 (방향이 앞에서 갈림)
- 근거: 온보딩 가이드 2-1 「직무와 장르의 경계보다 문제 해결을 우선합니다」

**에이전트·스킬 라우팅 확정 (2026-08-20)**
- 문제: 에이전트 30개 · 스킬 9개 → 케이스별로 뭘 부를지 사람이 못 외움 (v8 브랜드 제안 탭의 실제 고충)
- 해법: **케이스에서 출발하지 않는다.** 24칸(8유형 × 3단계)에 각각 「여기서 부르는 것」을 박아 넣음
- 단계 칩에 한 줄 추가: 에이전트/스킬 칩 + 그게 뭘 해주는지 한 줄
- 공통 게이트: 내보내기 직전 `delivery-gate`·`tone-guardian` / 수치 있으면 `fact-checker`
- 프로젝트 아닌 상황(견적·미팅·계약·채용·외주·인덱스)만 별도 목록 유지
- **문서 드리프트 발견**: CLAUDE.md는 에이전트 25종·스킬 4종으로 기재, 실제는 30종·9종 → 정리 필요
