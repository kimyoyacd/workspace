# 프로젝트 노트 관리 규칙

> 목적: 시안·리서치가 쌓여 대화가 길어지면 새 대화창을 열게 되는데, 그때 산출물 전체를 다시 훑지 않고
> **노트 파일의 요약 섹션만 읽어도** 프로젝트를 바로 재개할 수 있어야 한다.

## 파일 생성 — 진입점(entry point) 규칙
- 신규 프로젝트 시작 시 `.claude/projects/` 아래에 프로젝트별 노트 파일을 생성한다.
- **파일 하나로 끝나는 프로젝트**: `YYYYMM_프로젝트명.md` 가 곧 노트 파일이다.
- **산출물이 여러 개라 폴더가 필요한 프로젝트** (`.claude/projects/YYYYMM_프로젝트명/` 폴더 형태): 폴더 안에 `_note.md`를 만들고, 이것이 그 프로젝트의 **유일한 진입점**이 된다. 리서치·시안·덱 HTML 등 다른 파일은 전부 산출물이지 진입점이 아니다 — `_note.md`에서 파일명으로만 링크한다.
- 신규 노트 파일은 `.claude/library/prompts/project-note-template.md` 구조를 그대로 복사해서 시작한다.

## 파일 구성
각 노트 파일은 헤더(클라이언트·업무 범위·일정·견적·상태) + **요약 섹션** + **원본 로그 섹션**으로 구성한다.

- **요약 섹션**: 항상 "최신 결정사항·근거·다음 액션"만 담고, 매 세션 종료 시 덮어써서 갱신한다.
- **원본 로그 섹션**: 세션의 논의·시행착오·버려진 대안을 날짜 헤더로 append만 한다 (절대 덮어쓰거나 삭제하지 않음).

요약만 남기면 결정 근거·뉘앙스가 유실되므로, 디테일은 로그에 보존하고 요약은 결론 위주로 압축한다.

## 새 대화창에서 기존 프로젝트를 재개할 때
1. 해당 프로젝트의 노트 파일(또는 폴더의 `_note.md`) **요약 섹션만** 먼저 읽는다.
2. 그걸로 부족할 때만 원본 로그 → 산출물(HTML·리서치 md) 순서로 필요한 부분만 추가로 연다. 산출물 전체를 처음부터 다시 읽지 않는다.
3. 노트 파일이 없는 오래된 프로젝트 폴더를 만나면, 먼저 `_note.md`를 만들어 기존 산출물을 요약해 넣고 나서 작업을 이어간다.
