# MAX OS 사이트 IA 및 Claude Code 구현 브리프

버전: IA v0.1  
목적: 기존 MAX OS Dashboard v8, Figma의 MAX실 AI 워크플로우, Claude Code 온보딩 내용을 하나의 내부 운영 사이트로 통합한다.

---

## 1. 제품 정의

MAX OS 사이트는 프로젝트 결과물을 전시하는 사이트가 아니다. MAX실 구성원이 다음 다섯 가지 질문에 빠르게 답하도록 돕는 내부 운영 포털이다.

1. 오늘 무엇을 확인하고 결정해야 하는가?
2. 현재 업무·일정·리소스에 어떤 위험이 있는가?
3. 새 업무는 어떤 워크플로우로 시작해야 하는가?
4. Claude Code의 Agent·Skill·Gate는 어떻게 작동하는가?
5. 완료한 결과를 어디에 보관하고 어떻게 재사용하는가?

핵심 사용자:

- 실장·운영 매니저: 전체 현황, 리스크, 승인 대기, 리소스 판단
- 크리에이티브 디렉터: 전략·콘셉트·디자인·영상 Gate 검수
- 실무 디자이너: 업무 시작, 단계 확인, Skill 활용, 산출물·자산 등록
- 신규 구성원: MAX OS와 Claude Code 온보딩, 역할별 학습

## 2. 내비게이션 원칙

### 결론: 상단과 좌측 내비게이션을 함께 사용한다

- 상단 내비게이션: MAX OS의 큰 영역을 이동하는 전역 메뉴
- 좌측 내비게이션: 선택한 영역 안의 세부 기능을 이동하는 로컬 메뉴
- 상단과 좌측에 같은 메뉴를 반복하지 않는다.
- 홈은 메시지 전달과 빠른 진입이 중요하므로 좌측을 72px 아이콘 레일로 축소한다.
- 내부 페이지는 좌측을 224px로 확장해 한글 메뉴명을 항상 노출한다.
- 모바일·태블릿에서는 좌측 메뉴를 드로어로 전환한다.

### 좌측 전역 메뉴

데스크톱에서는 224px 고정 사이드바로 항상 한글 메뉴명을 노출한다.

1. 홈
2. 운영 현황
3. 업무 시작
4. 워크플로우
5. AI 실행 환경
6. AI 자산 라이브러리
7. 역할·운영 기준
8. 온보딩·실행 가이드
9. 도움말·지원

상단은 메뉴가 아니라 다음 유틸리티만 둔다.

- 통합 검색
- 알림·승인 대기
- 조직 선택·사용자 프로필

| 전역 영역 | 좌측 메뉴 |

### 중복 제거 원칙

- 홈의 수치는 `오늘 확인할 요약`만 보여준다.
- 운영 요약은 수치와 추세를 분석한다.
- 프로젝트 현황은 업무의 상태·단계·마감을 보여준다.
- 리소스·위험은 사람별 가동률·과부하·추가투입 필요를 보여준다.
- 일정·Gate는 승인 대기와 다음 단계 진입 가능 여부를 보여준다.
- 동일한 수치를 여러 페이지에 반복할 경우 상세 페이지 링크만 제공한다.

## 5. 페이지별 콘텐츠 명세

### 5.1 홈 `/`

목적: MAX OS의 의미와 오늘의 운영 상태를 짧게 전달하고, 상세 운영 화면으로 자연스럽게 연결하는 여백 있는 홈 포털이다.

상단 Hero:

- 인사: `Hello 👋 김효정님`
- 핵심 메시지: `일이 들어온 순간부터 실행·검수·자산화까지, MAX실의 일하는 방식을 연결합니다.`
- 보조 문장: `일이 들어온 순간부터 실행·검수·자산화까지 MAX실의 운영을 연결합니다.`
- 첨부된 `MAX_OS_HOME_WIREFRAME.html`의 여백과 메시지 비중을 그대로 유지한다.

오늘의 운영 요약:

- 진행 중 프로젝트 수
- 승인 대기 수
- 7일 이내 마감 수
- 위험 프로젝트 수

리소스 요약:

- `가동 리소스`와 `유휴 리소스`를 가장 큰 숫자로 표시한다.
- 홈에서는 인원 수와 상태만 보여주며 담당자별 가동률·과부하 원인·가용 시간은 표시하지 않는다.
- 두 수치는 `운영 현황 > 리소스·위험`의 해당 필터 화면으로 연결한다.

하단 보조 영역:

- 업무 워크플로우: UI 구축·콘텐츠 제작 · AI 비주얼 에셋 · AI 영상·필름
- 처음이라면: MAX OS 이해 · Claude Code 시작 · 첫 업무 체크
- 최근 구축된 시스템: Agent·Skill·템플릿·워크플로우 업데이트

홈에는 프로젝트 표, 담당자 명단, 개인별 가동률, 위험 사유, Gate 대기 목록, 2주 예측 그래프를 넣지 않는다. 이 정보는 `운영 현황`의 로컬 탭에서 확인하며, 홈의 모든 숫자는 해당 상세 화면으로 연결한다.

### 5.2 업무 시작 `/start`

목적: 사용자가 Agent·Skill 이름을 몰라도 올바른 업무 흐름으로 진입하게 한다.

5단계 시작 흐름:

1. 요청 입력: 클라이언트·목적·납기·산출물·참고자료
2. 진입 경로 선택: 제안·RFP · 바로 제작
3. 유형 선택: UI 구축·콘텐츠 제작 · AI 비주얼 에셋 · AI 영상·필름
4. 추천 확인: 적용 워크플로우 · 필요한 입력 · 담당 역할 · 예상 Gate
5. 작업 공간 생성: Project SoT 초안과 첫 체크리스트 생성

주요 출력:

- 추천 워크플로우
- 실행 단계
- 호출 Agent·Skill
- 사람의 결정이 필요한 Gate
- 생성될 산출물

### 5.3 운영 요약 `/operations/overview`

목적: 실장·운영자가 1분 안에 현재 상태와 조치 필요 항목을 파악한다.

상단 필터:

- 기간
- 팀 VM·VX·전체
- 업무 유형
- 프로젝트 상태

핵심 KPI:

- 진행 중 업무 수
- D-7 마감 업무 수
- Human Review 대기 수
- 평균 가동률
- 과부하 위험 인원 수

그래프·시각화:

- 주간 처리량: 라인·영역 그래프
- 단계별 업무 분포: 세그먼트 바
- 유형별 비중: 도넛 차트
- 팀 가동률: 사람별 불릿 바 또는 히트맵
- Gate 적체: 대기 시간별 가로 막대
- 위험 이벤트: 타임라인 마커

하단 액션 큐:

- 오늘 결정할 것
- 마감 임박
- 데이터 누락
- 추가투입 검토

### 5.4 프로젝트 현황 `/operations/projects`

목적: 모든 실행 업무를 상태·유형·Gate 기준으로 찾고 비교한다.

보기 방식:

- 카드 보기
- 테이블 보기
- 간트 보기

간트 필수 기능:

- 일·주·월 단위 전환
- 프로젝트별 행과 Task 하위 행
- Task 의존성·Milestone·Human Gate·납기·오늘 기준선
- 계획 일정과 실제 일정 비교
- 담당자·팀·상태 필터와 지연·충돌 표시

필수 필드:

- 프로젝트명·클라이언트
- 업무 유형
- 담당자
- 상태
- 현재 단계·현재 Gate
- 시작일·마감일
- 난이도
- 리스크
- SoT·최근 동기화

프로젝트 상세 `/operations/projects/:id`:

- 요약
- 일정·Gate
- 담당 역할
- 산출물
- Review 기록
- Project SoT
- 자산화·재사용 결과

상세 탭은 `요약 · Task · 일정·간트 · 리소스 · Gate·Review · 산출물 · Project SoT · 이력`으로 구성한다.

### 5.4.1 Task·스프린트 `/operations/tasks`

보기 방식:

- 주간 타임라인
- Kanban
- 목록

Task는 ID·프로젝트·워크플로우 단계·담당자·협업자·기간·우선순위·상태·예상시간·실제시간·의존성·차단 사유·Gate·산출물 근거를 가진다.

Kanban 상태는 `할 일 · 진행 중 · 검수 중 · 승인 대기 · 완료 · 차단`으로 구분한다.

### 5.5 일정·Gate `/operations/gates`

목적: 프로젝트 진척이 아니라 `사람의 판단이 필요한 대기 항목`을 관리한다.

콘텐츠:

### 5.11 UI 구축·콘텐츠 제작 `/workflows/digital-build`

공통 종료:

`Human Review → Project SoT → 승인 산출물 저장 → 사용·성과 학습`
