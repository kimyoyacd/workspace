우리가 일하는 방식

도구보다 먼저 합의된 건 태도예요. 아래 원칙은 MAX실의 모든 업무에 똑같이 적용돼요. 더 자세한 기준은 우리가 일하는 기준에서 볼 수 있어요.

PRINCIPLE 01

AI가 많은 방향을 탐색해도, 최종 선택은 사람이 해요

후보를 넓히는 건 AI의 일, 방향을 결정하는 건 우리의 일이에요. 선택의 책임은 언제나 사람에게 있어요.

PRINCIPLE 02

결과물은 공식 기준 문서와 보관함에 쌓아요

개인 폴더나 채팅에 흩어진 결과는 팀의 자산이 되지 못해요. 확정된 내용은 공식 기준 문서(Project SoT)에, 통과한 결과물은 Figma 자산 파일에 남겨요.

PRINCIPLE 03

사람의 승인이 필요한 단계는 건너뛰지 않아요

방향 결정·캐스팅 확정·최종 승인·권리 확인은 아무리 바빠도 생략하지 않아요. 빨리 가는 것보다 되돌아오지 않는 게 더 빨라요.

PRINCIPLE 04

잘된 방법도, 실패한 시도도 팀과 공유해요

좋은 프롬프트·잘 안 된 접근·재작업 원인을 기록하고 나누는 팀이 더 빨리 좋아져요. 혼자만 아는 노하우는 팀의 실력이 아니에요.

PRINCIPLE 05

도구 이름보다 일의 목적을 먼저 말해요

"어떤 Agent 쓰지?"보다 "무엇을 만들어야 하지?"가 먼저예요. 목적을 자연스러운 말로 요청하면 시스템이 알맞은 방법을 찾아줘요.

PRINCIPLE 06

기록이 남아야 다음 사람이 이어서 할 수 있어요

어떤 후보가 있었고 왜 이걸 골랐는지 남겨요. 담당자나 도구가 바뀌어도 같은 품질로 다시 만들 수 있는 게 목표예요.

첫 업무 체크리스트

실습

작은 일 하나를 처음부터 끝까지 해보는 게 목표예요. 여섯 단계를 순서대로 지나면 MAX OS의 한 사이클을 경험하게 돼요.

  1. 요청 입력

    새 업무 시작하기에서 클라이언트·목적·마감을 평소 말하듯 적어요.

  2. 유형 선택

    UI 구축·콘텐츠 제작 / AI 비주얼 에셋 / AI 영상·필름 중 하나를 골라요. 헷갈리면 워크플로우에서 비교해요.

  3. 실행

    추천된 흐름을 따라 진행해요. 단계별 방법은 해당 워크플로우 페이지에 있어요.

  4. 결과 확인

    만들어진 결과물을 직접 열어 보고, 요청한 내용과 맞는지 살펴봐요.

  5. 승인 요청

    사람의 확인이 필요한 단계라면 결정권자에게 승인을 요청해요. 대기 현황은 일정·Gate에서 보여요.

  6. 보관

    통과한 결과물을 Figma 자산 파일에 남겨요. 여기까지 하면 한 사이클 완료예요.

자주 묻는 질문

새 일은 어디서 시작하나요?
새 업무 시작하기에서 요청을 적으면 돼요. 유형을 고르면 알맞은 흐름을 추천해줘요.
제 확인을 기다리는 일은 어디서 보나요?
운영 현황의 일정·Gate에 모여 있어요. 상단 알림 아이콘으로도 갈 수 있어요.
Claude Code에서 오류가 나요. 어떻게 하죠?
AI와 일하기의 문제 해결을 먼저 확인하세요. 같은 증상이 없으면 팀에 공유해주세요 — 해결법이 문서에 추가돼요.
완성한 결과물은 어디에 두나요?
검수를 통과한 결과물만 Figma 자산 파일에 올려요. 보관 기준은 우리가 일하는 기준의 품질 기준에 있어요.
업무 유형별로 어떻게 진행하는지 궁금해요.
워크플로우에 유형별 단계·준비물·승인 시점이 정리되어 있어요. 전체 흐름은 전체 AX 시스템에서 한눈에 볼 수 있어요.
