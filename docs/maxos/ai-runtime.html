MAX OS · AI RUNTIME

AI와 함께 일하는 방법을 알아보세요

MAX실이 리서치·시안·영상·산출물 작업을 AI로 실행하는 공간이에요. Claude Code는 이 환경에서 쓰는 실행 도구 중 하나예요.

개요 Claude Code 프로젝트 구조 Agent·Skill 연결 상태 사용 가이드 문제 해결

AI 실행 환경이 무엇인가요

말로 요청하면 AI가 리서치·검수·산출물 제작을 대신 실행해 주는 작업 공간이에요. 요청은 한국어 문장으로 하고, 결과는 문서·HTML·이미지 같은 파일로 받아요.

이 환경은 세 가지로 이루어져 있어요.

  • 실행 도구 — Claude Code(대화형 실행 도구·터미널에서 실행)를 기본으로 써요.
  • 일하는 규칙 — 저장소의 CLAUDE.md가 톤·검수·산출물 기준을 정해요. AI는 매 세션 이 규칙을 먼저 읽어요.
  • 이 정보가 연결된 곳 — Notion 프로젝트 DB·시간 기록 시트·GitHub 저장소가 연결돼 있어요. 연결 상태 탭에서 확인할 수 있어요.

이런 일을 맡길 수 있어요

  • RFP 분석·시장조사·레퍼런스 수집 같은 리서치
  • 시안 검수·수치 검증·발송 전 점검 같은 검수
  • 제안서 덱·리포트·인덱스 페이지 같은 HTML 산출물 제작
  • 영상 스토리보드·무드보드·비주얼 프롬프트 같은 제작 준비
  • 견적 원가표·마진 시나리오 같은 초안 계산

이런 일은 맡기면 안 돼요

아래 결정은 사람의 승인이 필요해요. AI는 초안과 근거까지만 만들어요.

  • 최종 견적가·마진 결정 — 실장이 확정해요
  • 클라이언트에게 보내는 최종 발송 — 사람이 검토 후 보내요
  • 계약·NDA 판단 — 법무 검토를 대체하지 않아요
  • 출처 없는 수치를 그대로 쓰는 일 — 검증 불가 수치는 재검증 필요로 표기해요

처음이라면 이 순서로 시작하세요

STEP 1Claude Code 여는 방법 익히기

설치·저장소 열기·연결 확인까지, Claude Code 탭의 순서를 그대로 따라 하면 돼요.

STEP 2첫 요청 한 문장 보내기

사용 가이드 탭의 예시 문장을 그대로 복사해서 보내 보세요. 결과 파일이 어디에 생기는지 확인해요.

STEP 3내 업무로 실습하기

실제 진행 중인 일 하나를 골라 검수나 리서치부터 맡겨 보세요. 처음 시작하기 메뉴에 역할별 경로가 있어요.

Claude Code 사용설명서

Claude Code는 터미널에서 대화로 일을 시키는 실행 도구예요. 아래 여덟 항목을 순서대로 열어 보면 처음 설치부터 문제 해결까지 이어져요. 각 항목은 언제 필요한가 → 준비물 → 따라 하기 → 정상 결과 → 실패 시 조치 → 관련 템플릿 순서로 정리했어요.

01처음 시작무엇을 할 수 있는지 · 첫 실행▾

언제 필요한가

Claude Code를 한 번도 써 본 적이 없거나, 무엇을 맡겨도 되는지 감이 없을 때 읽어요.

준비물

  • 회사 계정으로 로그인할 수 있는 상태
  • MAX실 작업 저장소(workspace)에 접근 권한

따라 하기

  1. 개요 탭에서 맡길 수 있는 일 / 맡기면 안 되는 일을 먼저 구분해요.
  2. 터미널에서 작업 저장소 폴더로 이동한 뒤 claude를 입력해 실행해요.
  3. 첫 요청으로 "지금 진행 중인 프로젝트 노트 목록 보여줘"처럼 읽기만 하는 요청을 보내요.

정상 결과

대화 화면이 열리고, .claude/projects/ 안의 프로젝트 노트 목록을 답으로 받아요. 파일이 바뀌는 작업은 아직 일어나지 않아요.

실패 시 조치

실행 명령을 찾지 못하면 아래 02 설치·연결을 먼저 진행해요. 로그인 오류가 나면 계정 담당자(실장)에게 권한을 확인해요.

관련 템플릿

첫 요청 문장 예시는 사용 가이드 탭에 있어요.

02설치·연결환경 확인 · 저장소 열기 · 도구 연결▾

언제 필요한가

새 컴퓨터를 받았거나, Claude Code가 실행되지 않거나, Notion·Figma 같은 외부 도구 연결(MCP)이 필요할 때예요.

준비물

  • 터미널 사용이 가능한 컴퓨터
  • GitHub 계정과 저장소 접근 권한
  • 연결할 도구의 계정(Notion·Google 등)

따라 하기

  1. 공식 설치 안내에 따라 Claude Code를 설치하고 로그인해요.
  2. 작업 저장소를 내 컴퓨터로 복제(clone)한 뒤 그 폴더에서 실행해요.
  3. 외부 도구 연결(MCP·Model Context Protocol, 도구를 AI에 이어주는 방식)은 연결 담당 안내에 따라 추가해요.
  4. "CLAUDE.md 요약해줘"라고 보내 규칙 파일을 읽는지 확인해요.

정상 결과

실행하면 저장소 이름이 표시되고, CLAUDE.md 요약을 답으로 받아요. 연결한 도구는 연결 상태 탭의 표기와 같아야 해요.

실패 시 조치

저장소가 안 열리면 GitHub 권한을 먼저 확인해요. 도구 연결이 안 되면 문제 해결 탭의 연결 실패 항목을 따라 해요.

관련 템플릿

연결 대상 목록은 .claude/library/data-sources.md(연결 주소록)에 있어요.

03프로젝트 구조규칙·에이전트·산출물이 있는 곳▾

언제 필요한가

결과 파일이 어디에 생기는지, AI가 어떤 규칙을 따르는지 궁금할 때예요.

준비물

없음 — 읽기만 하면 돼요.

따라 하기

  1. CLAUDE.md(운영 규칙) → .claude/(에이전트·스킬·자산·프로젝트 노트) → docs/(산출물) 순서로 폴더를 열어 봐요.
  2. 진행 중인 프로젝트의 공식 기준 문서(Project SoT)를 .claude/projects/YYYYMM_프로젝트명.md에서 찾아 읽어요.

정상 결과

내 프로젝트의 노트 파일과 산출물 폴더 위치를 바로 짚을 수 있어요.

실패 시 조치

프로젝트 노트가 없으면 "○○ 프로젝트 노트 만들어줘"라고 요청해요. 규칙에 따라 자동으로 생성돼요.

관련 템플릿

자세한 폴더 설명은 프로젝트 구조 탭, 노트 작성 규칙은 .claude/library/project-note-rules.md에 있어요.

04요청 작성법좋은 요청의 조건 · 수정 요청▾

언제 필요한가

결과가 기대와 다르게 나오거나, 요청을 몇 번씩 다시 쓰게 될 때예요.

준비물

  • 클라이언트 이름과 이번 일의 목적
  • 납기와 원하는 산출물 형태
  • 참고자료(파일 위치·링크)

따라 하기

  1. 다섯 가지 필수 입력 — 클라이언트·목적·납기·산출물·참고자료 — 를 한 문단에 담아요.
  2. 수정할 때는 전체를 다시 쓰지 말고 어느 부분을, 왜, 어떻게 바꿀지 짚어서 말해요.

정상 결과

한 번의 요청으로 방향이 맞는 초안이 나오고, 수정 요청은 해당 부분만 바뀌어요.

실패 시 조치

결과가 계속 어긋나면 요청에 빠진 필수 입력이 없는지 확인하고, AI에게 "먼저 확인할 질문 있으면 물어봐"라고 요청해요.

관련 템플릿

바로 쓸 수 있는 예시 세 개가 사용 가이드 탭에 있어요.

05Agent·Skill자동으로 붙는 전문가 도구▾

언제 필요한가

"검수해줘"라고만 했는데 여러 단계가 자동으로 실행되는 이유가 궁금할 때, 또는 특정 전문 작업을 정확히 부르고 싶을 때예요.

준비물

없음 — 이름을 몰라도 자연어로 요청하면 알맞은 에이전트가 자동으로 붙어요.

따라 하기

  1. 평소처럼 하고 싶은 일을 문장으로 요청해요. 예: "코웨이 시안 검수해줘".
  2. AI가 어떤 에이전트를 쓰는지 실행 중에 표시돼요. 결과 요약에서 단계별 산출을 확인해요.
  3. 특정 에이전트를 지정하고 싶으면 이름을 함께 말해요. 예: "fact-checker로 이 수치 검증해줘".

정상 결과

검수 요청이면 검수 → 수치 검증 → 발송 전 점검이 파이프라인으로 이어지고, 각 단계 결과가 요약돼 나와요.

실패 시 조치

엉뚱한 에이전트가 붙으면 원하는 에이전트 이름을 지정해 다시 요청해요. 전체 목록은 Agent·Skill 탭에 있어요.

관련 템플릿

에이전트 정의 파일은 .claude/agents/, 스킬은 .claude/skills/에 있어요.

06권한·사람의 승인자동 실행 범위 · 승인이 필요한 일▾

언제 필요한가

AI가 어디까지 알아서 하고, 어디부터 사람의 승인이 필요한지 경계를 알고 싶을 때예요.

준비물

없음 — 규칙만 알면 돼요.

따라 하기

  1. 자동 실행 — 리서치·초안·검수·저장소 안 파일 작업은 AI가 진행해요.
  2. 사람의 승인이 필요해요 — 최종 견적가·마진, 클라이언트 발송, 계약 판단은 반드시 사람이 확정한 뒤에 진행돼요. 진행 중 "잠깐" 또는 "여기서 멈춰"라고 하면 그 단계에서 대기해요.
  3. 금지 작업 — 출처 없는 수치 사용, 승인 없는 대외 발송은 규칙으로 막혀 있어요.

정상 결과

승인이 필요한 지점에서 AI가 멈추고 확인을 요청해요. 확인 전에는 다음 단계로 넘어가지 않아요.

실패 시 조치

승인 없이 진행된 것처럼 보이면 즉시 멈추게 하고, 결과물을 발송하기 전에 검수 파이프라인(design-critique → fact-checker → delivery-gate)을 다시 돌려요.

관련 템플릿

검수 기준은 .claude/library/qc-checklist.md, 대외 메일 톤은 .claude/library/mail-tone.md를 따라요.

07문제 해결막혔을 때 여기부터▾

언제 필요한가

연결이 끊기거나, 파일이 충돌하거나, 결과가 요청과 다를 때예요.

준비물

  • 문제가 난 요청 문장과 결과 화면
  • 작업하던 파일 경로

따라 하기

  1. 문제 해결 탭에서 내 상황과 같은 케이스(연결 실패·파일 충돌·근거 부족·결과 불일치)를 찾아요.
  2. 케이스별 조치를 순서대로 따라 해요.
  3. 해결이 안 되면 문제 상황을 그대로 캡처해 실장(김효정)에게 공유해요.

정상 결과

네 가지 케이스 중 하나로 분류되고, 그 자리에서 조치 방법을 찾을 수 있어요.

실패 시 조치

같은 문제가 반복되면 이 페이지의 해당 항목을 업데이트하도록 요청해서 팀 전체가 같은 문제를 겪지 않게 해요.

관련 템플릿

케이스별 상세 조치는 문제 해결 탭에 있어요.

08업데이트규칙·도구가 바뀌었을 때▾

언제 필요한가

CLAUDE.md 규칙·에이전트·스킬이 바뀌었거나, Claude Code 자체가 업데이트됐을 때 무엇이 달라졌는지 확인하려는 경우예요.

준비물

저장소 최신 상태(git pull로 받아 둔 상태)

따라 하기

  1. 저장소를 최신으로 받은 뒤 "최근 CLAUDE.md와 에이전트 변경 내용 요약해줘"라고 요청해요.
  2. 바뀐 규칙이 내 업무에 영향을 주는지 — 특히 검수 기준·산출물 규칙 — 확인해요.
  3. 새 스킬·에이전트가 추가됐으면 예시 요청 한 번으로 동작을 익혀요.

정상 결과

무엇이 언제 바뀌었고, 내 작업 방식에서 무엇을 새로 익혀야 하는지 목록으로 받아요.

실패 시 조치

업데이트 후 기존 요청이 다르게 동작하면, 변경 전 방식이 필요한 이유를 실장에게 공유하고 규칙 조정을 논의해요.

관련 템플릿

자동화·스케줄 변경은 .claude/library/automation.md에서 함께 확인해요.

저장소가 이렇게 생겼어요

AI가 일할 때 읽는 규칙과 만들어 내는 결과물이 전부 한 저장소 안에 있어요. 아래 다섯 곳만 알면 돼요.

workspace/
├── CLAUDE.md              ← 운영 규칙 · AI가 매 세션 처음 읽는 파일
├── .claude/
│   ├── agents/            ← 에이전트 정의 (전문가 역할 카드)
│   ├── skills/            ← 스킬 (덱 디자인 등 반복 작업 묶음)
│   ├── library/           ← 재사용 자산 (톤·토큰·견적표·체크리스트)
│   └── projects/          ← 공식 기준 문서(Project SoT) · YYYYMM_프로젝트명.md
└── docs/                  ← 산출물 (HTML 덱·리포트·이 사이트)

규칙　CLAUDE.md

MAX실이 일하는 방식의 원본이에요. 메일 톤, 검수 순서, 산출물 규칙, 파이프라인이 여기 적혀 있어요. AI는 어떤 요청이든 이 규칙 안에서 실행해요.

규칙을 바꾸고 싶으면 이 파일을 고치면 돼요 — 다음 세션부터 바로 적용돼요.

전문가　.claude/agents · .claude/skills

좋은 요청에는 다섯 가지가 들어가요

이 다섯 가지를 한 문단에 담으면, 한 번의 요청으로 방향이 맞는 결과가 나와요. 없는 항목은 "없음"이라고 말해도 돼요 — 비워 두는 것보다 나아요.

클라이언트 — 누구 일인가요 목적 — 왜 하나요 납기 — 언제까지 필요한가요 산출물 — 어떤 형태로 받을까요 참고자료 — 무엇을 보고 하면 되나요

이렇게 요청해 보세요

코웨이 시안 검수해줘

무슨 일이 생기나요 — 시안을 여섯 영역으로 검수하고 수치 검증·발송 전 점검까지 이어져요.

더 정확하게 — 시안 파일 위치와 "내일 오전 회신 예정"처럼 납기를 붙이면 우선순위가 잡혀요.

30초 브랜드 영상 스토리보드와 사운드 방향을 잡아줘

무슨 일이 생기나요 — 컷별 콘티와 음악·효과음 방향이 함께 나와요.

더 정확하게 — 브랜드 이름·전달 메시지·참고 영상 링크를 붙이면 톤이 처음부터 맞아요.

20대 여성 인물 에셋을 5개 포즈로 파생해줘

무슨 일이 생기나요 — 기준 인물에서 포즈 변형 에셋을 만들어요.

더 정확하게 — 기준 인물 이미지 위치와 쓰일 채널(상세페이지·배너)을 붙이면 규격까지 맞춰요.

수정은 이렇게 요청하세요

전체를 다시 시키면 잘된 부분까지 바뀔 수 있어요. 어느 부분을 · 왜 · 어떻게 세 가지를 짚어 주세요.

  • 어느 부분을 — "두 번째 섹션의 헤드카피가"
  • 왜 — "클라이언트가 기능보다 감성을 원해서"

케이스 1　연결 실패

무슨 상황인가요

Notion·시트 데이터가 안 불러와지거나, 화면에 "불러오지 못했어요"가 떠요.

어떤 영향이 있나요

숫자가 비어 보이거나 오래된 값으로 남아요. 이미 만든 산출물 파일은 영향받지 않아요.

이렇게 해 보세요

  1. 화면 하단의 데이터 기준 시각을 확인해요 — 어제 아침 7시 이후면 정상 범위예요.
  2. 다음 자동 갱신(매일 아침 7시)까지 기다리거나, 급하면 원본(Notion·시트)을 직접 열어 확인해요.
  3. 이틀 이상 멈춰 있으면 실장에게 알려 갱신 작업 상태를 확인해요.

케이스 2　파일 충돌

무슨 상황인가요

같은 파일을 두 곳에서 고쳐서 저장소에 올릴 때 충돌(conflict) 메시지가 나와요.

어떤 영향이 있나요

해결 전까지 그 파일의 새 버전을 올릴 수 없어요. 다른 파일 작업은 그대로 할 수 있어요.

이렇게 해 보세요

  1. 억지로 덮어쓰지 말고 멈춰요 — 다른 사람의 작업이 지워질 수 있어요.
  2. AI에게 "이 충돌 상황 설명해주고 양쪽 변경을 살려서 합쳐줘"라고 요청해요.
  3. 합친 결과를 눈으로 확인한 뒤에 올려요.

케이스 3　근거 부족

무슨 상황인가요

결과물의 수치·인용에 출처가 없거나, "재검증 필요" 표시가 붙어 있어요.

어떤 영향이 있나요

그대로 클라이언트에게 나가면 신뢰 문제가 생겨요. 발송 전에 반드시 걸러야 해요.

이렇게 해 보세요

  1. "fact-checker로 이 문서 수치 전부 검증해줘"라고 요청해요.
  2. 검증된 수치는 출처 링크가 붙고, 확인 안 되는 수치는 "업계 추정 · 재검증 필요"로 바뀌어요.
  3. 재검증 필요로 남은 수치는 빼거나, 원출처를 직접 찾아 붙인 뒤 내보내요.

케이스 4　결과 불일치

무슨 상황인가요

요청한 것과 다른 결과가 나왔어요 — 방향이 어긋났거나, 엉뚱한 형식으로 나왔어요.

어떤 영향이 있나요

다시 시키는 시간이 들어요. 원인을 안 잡으면 같은 어긋남이 반복돼요.

이렇게 해 보세요

  1. 요청에 다섯 가지 필수 입력(클라이언트·목적·납기·산출물·참고자료)이 있었는지 확인해요.
  2. 전체 재요청 대신 "어느 부분을 · 왜 · 어떻게" 형식으로 수정을 요청해요.
  3. 프로젝트 기준과 어긋났다면 공식 기준 문서(Project SoT)를 같이 읽게 해요 — "이 프로젝트 노트 기준으로 다시 맞춰줘".
